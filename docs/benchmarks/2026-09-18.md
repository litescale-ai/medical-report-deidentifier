# Three local models, 18 September 2026

Fresh uncached sequential runs after separate warmup, using 20 synthetic searchable PDFs of 3 short pages each. All use the same local Ollama endpoint, structured JSON and thinking disabled. One run per model on an active Mac; not a repeated, isolated hardware benchmark.

Apple M4 Pro, 48 GiB RAM, macOS-15.1-arm64-arm-64bit. 20 documents, 60 pages, 7,560 extracted words. Tested commit `0b729dbdbac4572a13c1820bc75ca1d4b8bbe43c`.

The identifier check searches all exported text for 12 known values per document: patient, doctor and relative names, clinic, email, labelled and unlabelled street addresses, city, postal code, HPCSA number, practice number and telephone number. These are pipeline results, including deterministic removal rules, not raw model-only scores.

The stricter preservation check requires the entire clinical paragraph to remain on every page after whitespace normalization. The initial benchmark checked only three clinical phrases and missed false-positive replacements. It exposed Lee matching inside sleep and patient being treated as a name alias. Whole-identifier matching, generic alias filtering and fitted PDF labels fixed those cases. The table above is a fresh rerun after those fixes.

Generation speed is total output tokens divided by total Ollama generation duration. It excludes prompt processing, model loading and export work. Batch time includes discovery, manifest updates, redaction and verification, but excludes the separate warmup. Warmup and exact model revisions are retained in the JSON.

All three models are installed. Qwen3.5 2B is the first smaller-model candidate to trial for speed and its smaller download. Gemma E4B remains the default until broader representative documents have been reviewed. A faster token rate alone does not guarantee a faster batch: models emit different numbers of tokens.

This is a narrow synthetic regression benchmark, not a clinical accuracy validation. It does not measure general precision/recall, identity-linking accuracy, dense records, OCR/scanned documents, embedded Office images or metadata. File/folder names are not scrubbed. These repeated short pages are easier than varied real reports. Review real outputs before sharing.

48 offline regressions passed, including TXT, Markdown, HTML, XLSX, DOCX, PDF and PPTX, interrupted-run resume, source changes, preservation of user-edited outputs, OCR reuse and the Streamlit workflow with failed-file retries using a different model. OCR reuse was tested with a prepared layer; scanned-document OCR performance was not benchmarked.

## Reproduce

Use a fresh directory to avoid cached inference:

```bash
python scripts/benchmark_local.py --output /tmp/guardian-new-comparison
```
